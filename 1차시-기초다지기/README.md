## 1. 바이브 코딩의 등장 배경과 연구 현장 활용 사례

바이브 코딩은 코드를 직접 쓰는 대신 **하고 싶은 일을 자연어로 설명하면 AI가 코드를 작성하고 실행하는 방식**입니다.

- AI는 인식(Perception) → 생성(Generative) → 에이전트(Agentic) → 물리(Physical) AI로 발전하고 있습니다. AI가 직접 파일을 만들고 명령을 실행하는 "AI 코딩 에이전트"가 바로 에이전트 단계입니다.
- 연구 현장에서도 쓰입니다. 예를 들어 유전자 변이가 발현량에 주는 영향을 예측하는 일은 예전에는 데이터 수집에 수개월~수년, 학습과 예측에 3~5시간이 걸렸습니다. AlphaGenome 같은 AI 모델을 클로드 코드와 연결하면 한 문장으로 30~60초 만에 계산할 수 있습니다.

강의에서 보여 드린 연구용 프롬프트 예시입니다. AlphaGenome API 키와 AlphaGenome MCP 연결이 필요하므로 따라 하지 않으셔도 됩니다. MCP는 3차시에서 배웁니다.

```
AlphaGenome으로 ABI3 유전자의 변이를 하나씩 가상으로 바꿔가면서, 각 변이가 발현량에 미치는 영향을 계산해줘.
```

참고: AlphaGenome MCP 서버 소개는 [jolab.ai](https://www.jolab.ai)에 있습니다.

## 2. 클로드 아티팩트로 만드는 첫 웹페이지

설치 없이 브라우저에서 바로 바이브 코딩을 체험합니다. 무료 계정으로도 할 수 있습니다.

**순서 (2026년 10월 화면 기준)**
1. [claude.ai](https://claude.ai)에 로그인하고 왼쪽 사이드바에서 **[아티팩트]** 를 누릅니다.
2. "Make something new" 아래의 카드 중 **[Dashboard]** 를 선택합니다.
3. 아래 프롬프트를 입력하고, 클로드가 추가로 묻는 질문에 답합니다.
4. 완성되면 오른쪽 위 **[공유]** 버튼으로 링크를 만들어 다른 사람과 공유합니다.

```
오늘의 날짜와 시간, 검색창이 있는 나만의 시작 홈페이지를 만들고 싶어
```

> 책이나 예전 화면에 나오는 [새 아티팩트] 버튼, [처음부터 시작하기] 화면, [게시] 버튼은 2026년 10월에 없어졌습니다.

**바이브 코딩의 두 갈래: 만든 결과물이 어디에 남는가?**

| | 클로드 서버에 남는다 | 내 컴퓨터에 저장된다 |
|---|---|---|
| 도구 | 아티팩트(claude.ai), 클로드 디자인 | 클로드 코드, 클로드 데스크톱(코웍, 코드) |
| 결과물 | claude.ai 안에 저장, 링크로 공유 | 내 PC에 파일로 남음 |
| 이럴 때 | 설치 없이 바로 만들고 링크로 공유할 때 | 여러 파일로 된 진짜 프로젝트를 만들 때 |

## 3. 클로드 코드 설치와 첫 실행

설치 방법은 [00-시작하기](../00-시작하기/README.md)에 자세히 정리했습니다.

- Windows (파워셸): `irm https://claude.ai/install.ps1 | iex`
- macOS / Linux (터미널): `curl -fsSL https://claude.ai/install.sh | bash`
- 설치 후 **실습 폴더에서** 터미널을 열고 `claude` 입력

클로드 코드는 Pro 이상 요금제가 필요합니다. 터미널이 어렵다면 [클로드 데스크톱 앱](https://claude.com/download)의 Code 탭에서도 같은 일을 할 수 있습니다.

## 4. [실습 01] 손글씨 숫자 인식 프로그램 만들기

**MNIST 데이터세트**: 0부터 9까지의 손글씨 숫자 이미지 70,000장(훈련 60,000장, 테스트 10,000장), 28×28 픽셀 흑백 이미지입니다.

새 폴더(예: `실습01-손글씨인식`)에서 클로드 코드를 실행하고 입력합니다.

```
손글씨로 숫자를 입력하면 이것을 인식하는 코드를 만들어서 실행해 줘.
```

클로드 코드가 필요한 라이브러리 설치, 모델 학습, 실행 화면까지 진행합니다. 중간에 권한을 물으면 내용을 읽어 보고 허용하세요.

**더 해 보기**

```
숫자 인식 프로그램을 윈도우 탐색기에서 클릭해서 실행할 수 있게 해 줘.
```

## 5. [실습 02] 꼭 알아야 할 기본 명령어

클로드 코드 입력창에 `/`로 시작하는 명령을 입력합니다.

| 정보 확인 | 세션 관리 | 설정·도구 |
|---|---|---|
| `/help` 명령어 목록 | `/clear` 대화 초기화 | `/init` CLAUDE.md 생성 |
| `/status` 모델·계정 상태 | `/compact` 대화 압축 | `/model` 모델 전환 |
| `/context` 토큰 사용량 | `/rewind` 이전 상태로 되돌리기 | `/config` 설정 화면 |
| `/usage` 요금제 사용 한도 | | `/doctor` 상태 진단 |

**실습 과제**
1. 실습 과제 폴더에서 `claude` 실행
2. `/init`으로 프로젝트를 설정하고 CLAUDE.md 파일 만들기
3. `/context`로 토큰을 확인하고, `/compact`로 압축, `/clear`로 초기화
4. `/rewind`로 되돌려 보고, `/doctor`, `/model`, `/config`로 설정 살펴보기

> `Esc`를 두 번 누르면 `/rewind`와 같이 이전 시점으로 되돌아갈 수 있습니다. 전체 명령어는 [명령어 모음](../보충자료/명령어-모음.md)에 있습니다.

## 6. [실습 03] 5W1H와 PRD로 요구사항 정리하기

막연한 아이디어도 아래 여섯 질문에 답하다 보면 구체적인 기획이 됩니다.

| 질문 | 뜻 |
|---|---|
| Why: 왜 만드는가? | 목적과 동기 |
| Who: 누구를 위한 것인가? | 대상 사용자 |
| What: 무엇을 만들 것인가? | 핵심 기능과 내용 |
| When: 언제 사용되는가? | 사용 시점과 상황 |
| Where: 어디서 사용되는가? | 사용 환경과 플랫폼 |
| How: 어떻게 만들 것인가? | 구현 방식과 기술 |

**PRD(Product Requirements Document)** 는 개발자들이 코딩 전에 쓰는 제품 기획서입니다. 무엇을 만들지, 왜 필요한지, 어떻게 작동해야 하는지를 정리합니다. 좋은 프롬프트와 좋은 기획서는 본질이 같습니다.

## 7. [실습 03] PRD로 상식 퀴즈 게임 만들기

새 폴더(예: `실습03-퀴즈게임`)에서 클로드 코드를 실행하고, 먼저 PRD를 요청합니다.

```
아래의 상식 퀴즈 게임을 만드는 PRD를 작성해 줘.
게임 규칙:
- 4지선다 객관식 퀴즈
- 카테고리: 한국사, 과학, 지리, 예술과 문화
- 각 카테고리별 10문제씩 총 40문제
- 정답/오답 즉시 피드백
- 최종 점수 및 순위 기록
```

PRD를 읽어 보고 고칠 곳이 있으면 말로 수정을 요청한 뒤, 실행합니다.

```
작성된 PRD를 실행해줘
```

완성된 `index.html`을 브라우저로 열어 게임을 해 보세요. 이 퀴즈 게임은 2차시에서 계속 사용합니다. 혹시 완성하지 못했다면 [실습파일/상식퀴즈게임](../실습파일/상식퀴즈게임/)을 내려받아 2차시를 시작하면 됩니다.

**더 해 보기: 단계별로 나누어 만들기**

한 번에 만들기 어려운 큰 프로그램은 PRD를 단계로 나누면 결과가 안정적입니다.

```
상식 퀴즈 게임을 클로드 코드로 구현할 수 있도록 PRD를 바탕으로 3단계 프롬프트를 정리해 줘.
```

| 활용 | 방법 |
|---|---|
| 수업 안내 페이지 | 아티팩트로 강의 일정표·과제 안내 페이지를 만들고 링크로 공유 |
