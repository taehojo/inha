## 1. [실습 04] CLAUDE.md와 /init으로 프로젝트 규칙 정하기

**CLAUDE.md** 는 프로젝트의 구조, 코딩 스타일, 핵심 명령어 등을 적어 두는 설정 파일입니다. 클로드 코드는 시작할 때마다 이 파일을 자동으로 읽습니다.

| 역할 | 설명 |
|---|---|
| 맥락 유지 | 세션이 끊어져도 프로젝트 맥락을 복원 |
| 규칙 저장 | 코딩 스타일과 프로젝트 규칙을 기록 |
| 자동 로드 | 클로드 코드 시작 시 자동으로 읽음 |

퀴즈 게임 폴더에서 클로드 코드를 실행하고 입력합니다.

```
/init
```

클로드 코드가 프로젝트를 분석해 CLAUDE.md를 만듭니다. 이미 있으면 덮어쓰지 않고 개선할 점을 제안합니다.

## 2. [실습 04] /memory로 퀴즈 문항 검증 기준 추가하기

AI가 만든 퀴즈에는 정답이 둘이거나 기준이 모호한 문제가 섞이기 쉽습니다. 출제 원칙을 CLAUDE.md에 적어 두면 클로드 코드가 매번 그 기준을 지킵니다.

1. `/memory` 입력 → **Project memory**(프로젝트의 CLAUDE.md) 선택
2. 편집기에서 CLAUDE.md가 열리면 아래 가이드라인을 붙여 넣고 저장

```
퀴즈 문제 교차 검증 가이드라인
모든 문제 작성 시 확인 사항
1. 정답이 하나뿐인가?
- 다른 해석 가능 시 조건 명시 (예: 면적 기준, 2024년 기준)
2. 최상급 표현에 기준이 있는가?
- '가장 큰', '최초의' 등 표현에 측정 기준 명시
3. 시간과 범위가 명확한가?
- 변할 수 있는 정보는 시점 명시
- 지리적, 분류적 범위 한정
4. 교차 검증했는가?
- 의심스러운 정보는 2개 이상 출처 확인
- 논란 있는 내용은 주류 학설 기준
```

3. 잘 저장되었는지 확인합니다.

```
현재 프로젝트의 CLAUDE.md 내용을 확인해줘.
```

4. 기존 문제를 가이드라인으로 점검합니다.

```
지금까지 만들어진 문제를 방금 저장한 가이드라인을 참고해서 점검해 줘. 가이드라인에 맞지 않은 퀴즈와 정답이 있다면 이에 맞게 수정해줘.
```

완성 예시: [examples/CLAUDE.md](examples/CLAUDE.md)

> `/memory` 화면에서는 클로드가 스스로 기록하는 "자동 메모리"도 켜고 끌 수 있습니다. 직접 정한 규칙은 CLAUDE.md에, 클로드가 배운 내용은 자동 메모리에 쌓입니다.

## 3. [실습 05] 커스텀 명령어로 반복 작업 자동화하기

**커스텀 명령어**는 자주 쓰는 지시를 파일로 저장해 두고 `/이름`으로 불러 쓰는 나만의 단축 명령입니다.

**Step 1. 명령어 폴더 만들기**

```
현재 프로젝트에 커스텀 명령어 폴더를 만들어 줘.
.claude/commands 디렉터리를 생성하고 구조를 보여줘.
```

**Step 2. 명령어 파일 만들기**

```
.claude/commands/quiz-validate.md 파일을 만들어 줘.
퀴즈 문제 중에서 '가장', '최초', '최대' 같은 최상급 표현이 있는지 찾아서 목록으로 보여줘.
```

**Step 3. 실행하기**

```
/quiz-validate
```

**더 해 보기: 값을 넘겨받는 명령어**

```
.claude/commands/quiz-validate.md를 다음과 같이 수정해 줘.
사용자가 카테고리를 지정하면 해당 카테고리의 문제만 검증하고,
지정하지 않으면 전체 문제를 검증해 줘.
$ARGUMENTS에 입력된 값을 카테고리로 사용하면 돼.
검증할 때는 '가장', '최초', '최대' 같은 모호한 표현이 있는지 찾아서
어떤 기준을 명시해야 하는지 알려 줘.
```

이제 `/quiz-validate 과학`처럼 카테고리를 붙여 실행할 수 있습니다.

```
.claude/commands/quiz-range.md를 생성해.
$1번부터 $2번까지의 문제를 검토하는 기능을 만들어 줘.
문제의 난이도와 정답 분포를 확인하게 해 줘.
```

```
.claude/commands/quiz-add.md를 생성해.
새 퀴즈를 추가하는 명령어를 만들어 줘.
$1은 카테고리, $2는 난이도로 받아서 처리해.
기존 퀴즈들과 같은 형식으로 만들고, 검증 가이드라인을 꼭 지키게 해 줘.
```

완성 예시: [examples/.claude/commands/quiz-validate.md](examples/.claude/commands/quiz-validate.md)

> **참고: 커스텀 명령어와 스킬이 통합되었습니다.** `.claude/commands/quiz-validate.md`와 `.claude/skills/quiz-validate/SKILL.md`는 둘 다 `/quiz-validate`로 실행됩니다. 기존 commands 방식도 그대로 작동하고, 새로 만들 때는 스킬 형식이 권장됩니다. 스킬 형식 예시: [examples/.claude/skills/quiz-validate/SKILL.md](examples/.claude/skills/quiz-validate/SKILL.md). 스킬은 3차시에서 자세히 다룹니다.

## 4. 컨텍스트 관리: 긴 대화에서 품질 유지하기

**왜 필요한가**
- **컨텍스트 부패(context rot)**: 담을 수 있는 대화량(최대 100만 토큰)은 커졌지만, 모델이 한 번에 주의를 기울일 수 있는 양은 늘지 않습니다. 대화가 길어질수록 핵심 정보가 묻힙니다. 모니터에 탭 1,000개를 띄워 놓으면 정작 봐야 할 탭을 찾기 어려운 것과 같습니다.
- **`/compact`의 한계**: 저절로 압축되게 두면 무엇을 남길지 모델이 혼자 정하고, 그것도 대화가 가장 길어져 성능이 떨어진 순간에 정합니다. 최근 대화 위주로 기억해서 초반의 중요한 지시가 빠지기 쉽습니다.

**해결 방법 6가지**

| 방법 | 설명 |
|---|---|
| 1. 미리 압축하기 | 한계에 닿기 전에 직접 `/compact`를 실행합니다. 50~60% 정도 찼을 때가 자주 권장됩니다. |
| 2. 요약 방향 정해 주기 | `/compact` 뒤에 남길 내용을 적습니다. 예: `/compact 퀴즈 검증 규칙과 남은 할 일 위주로 남겨 줘` |
| 3. 외부 메모 활용 | 중요한 결정과 진행 상황을 .md 파일로 저장하게 합니다. |
| 4. `/clear` + 외부 메모 | 메모에 충분히 남겼다면 대화를 비우고 새로 시작합니다. 메모 파일이 다음 세션의 출발점이 됩니다. 중간중간 진행 상황을 되물어 확인하세요. |
| 5. 서브 에이전트에 맡기기 | 별도 컨텍스트에서 일하고 결론만 돌려받습니다. 중간 과정이 필요 없는 조사에 효과적입니다. |
| 6. `/rewind` 적극 활용 | 잘못된 답에 수정 지시를 덧붙이는 대신 `Esc` 두 번이나 `/rewind`로 문제 직전 시점으로 되돌립니다. |

`/context`로 지금 얼마나 찼는지 수시로 확인하세요.

## 5. API 키 발급과 .env로 안전하게 연결하기

**API(Application Programming Interface)** 는 프로그램과 프로그램을 잇는 다리입니다. 지금까지 만든 퀴즈 게임은 문제가 코드 안에 고정되어 있지만, API로 AI 모델을 연결하면 내 프로그램이 사진을 보고 판단하거나 글을 새로 쓸 수 있습니다.

**오픈라우터(OpenRouter)** 는 여러 AI 모델의 API를 한곳에 모아 둔 서비스입니다.
- 키 하나로 GPT, Claude, Gemini 등 여러 모델을 쓸 수 있습니다.
- 모델을 바꿔 가며 비교하기 쉽습니다.
- 무료 모델(이름 끝이 `:free`)도 있어 부담 없이 실습할 수 있습니다.

가입과 키 발급 방법은 [00-시작하기](../00-시작하기/README.md#오픈라우터-api-키-준비-2차시-전까지)에 있습니다.

**API 키를 .env로 안전하게 연결하기**

| 원칙 | 방법 |
|---|---|
| .env 파일 | 프로젝트 폴더에 `.env` 파일을 만들고 `OPENROUTER_API_KEY=발급받은키` 한 줄로 저장합니다. 코드 안에는 키를 직접 쓰지 않습니다. |
| .gitignore | `.env`를 `.gitignore`에 넣어 깃허브 등에 함께 올라가지 않게 합니다. |
| 공유 금지 | 키를 채팅·메일·슬라이드에 붙여 넣지 않습니다. 노출되면 바로 오픈라우터에서 삭제하고 새로 발급합니다. |
| 클로드 코드에 맡기기 | 아래 프롬프트 한 문장이면 .env를 읽는 코드와 .gitignore 설정까지 해 줍니다. |

새 폴더(예: `실습06-레시피앱`)에 `.env` 파일을 만들어 키를 저장한 뒤 입력합니다.

```
OpenRouter에서 받은 API 키를 .env 파일로 저장했어. 이 키를 안전하게 사용할 수 있도록 준비해 줘.
```

예시 파일: [examples/.env.example](examples/.env.example), [examples/.gitignore](examples/.gitignore)

> `.env`처럼 점(.)으로 시작하는 파일은 숨김 파일이라 탐색기에서 안 보일 수 있습니다. Windows 탐색기 [보기] → [표시] → [숨긴 항목]을 켜세요. 직접 만들기 어렵다면 클로드 코드에 "`.env` 파일을 만들어 줘. 키는 내가 직접 붙여 넣을게."라고 요청한 뒤 키는 편집기에서 직접 붙여 넣으세요. 키를 프롬프트 창에 쓰지는 마세요.

## 6. [실습 06] 사진 속 재료로 레시피 추천 앱 만들기

**텍스트 AI와 이미지 인식 AI**

| 텍스트 AI | 이미지 인식 AI |
|---|---|
| 텍스트를 입력하면 텍스트를 생성 | 이미지를 입력하면 분석 결과를 반환 |
| 질문 응답, 번역, 요약, 코드 작성 | 사진 속 물체, 텍스트, 상황 인식 |
| 예: "이 문장을 영어로 번역해줘" | 예: "냉장고 사진으로 레시피 추천해줘" |

**AI API로 만드는 냉장고를 부탁해**: ① 냉장고 사진 업로드 → ② 이미지 AI가 식재료 파악 → ③ 텍스트 AI가 레시피 제안. 두 AI API를 차례로 불러 하나의 서비스를 만듭니다.

**모델 고르기 (2026년 10월 기준 무료 모델 예)**
- `google/gemma-4-31b-it:free`: 이미지와 텍스트를 모두 처리하므로 두 단계 모두에 쓸 수 있습니다.
- `google/gemma-4-26b-a4b-it:free`: 이미지·텍스트 모두 가능한 조금 가벼운 모델

무료 모델 목록은 자주 바뀝니다. 오류가 나면 [openrouter.ai/models](https://openrouter.ai/models)에서 "free"로 검색해 지금 있는 모델로 바꾸세요.

**1) API 테스트**

```
이제 준비된 API가 실제로 작동하는지 테스트해 줘.
이미지 인식은 google/gemma-4-31b-it:free 모델을 이용하고,
텍스트 인식은 google/gemma-4-31b-it:free 모델을 이용할 거야.
API를 통한 텍스트와 이미지 인식을 각각 테스트해서 실행 결과를 알려줘.
```

**2) 3단계 PRD 만들기**

```
앞서 만든 OpenRouter API를 이용해서, 냉장고 사진에서 재료를 인식하고 레시피를 추천하는 웹 애플리케이션을 만들고 싶어. 다음과 같이 3단계로 나누어서 PRD를 만들어 줘.
1단계는 이미지를 입력받고 google/gemma-4-31b-it:free 을 사용해서 이미지를 인식해.
2단계는 1단계에서 얻은 정보와 google/gemma-4-31b-it:free 을 사용해서 레시피를 생성해.
3단계는 사용자 프로필을 만들어서 레시피를 저장해.
각 단계를 PRD_step1.md, PRD_step2.md, PRD_step3.md로 나누어 저장해 줘
```

**3) 단계별로 실행하고 테스트하기**

```
PRD_step1.md를 실행해.
```
```
메인 애플리케이션을 실행해서 1단계의 결과를 테스트해 줘.
```
```
PRD_step2.md를 실행해.
```
```
메인 애플리케이션을 실행해서 2단계의 결과를 테스트해 줘.
```
```
PRD_step3.md를 실행해.
```
```
메인 애플리케이션을 실행해서 3단계의 결과를 테스트해 줘.
```

테스트용 냉장고 사진: [실습파일/테스트입력](../실습파일/테스트입력/)의 `냉장고.jpg`, `냉장고2.jpg`

## 교수자를 위한 활용 포인트
